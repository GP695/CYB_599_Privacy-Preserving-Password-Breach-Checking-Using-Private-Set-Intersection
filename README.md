# CYB 599 Part 3 — Password Breach PSI (Reference Prototype)

## Critical implementation status
This repository is a **working functional reference prototype**, not a completed cryptographic BFV implementation. It implements and tests the Part 2 encoder, NFC normalization, 14-bit bin selection, 64-bit item encoding, bin padding/shuffling, degree-8 root-polynomial membership logic, and a plaintext baseline. The benchmark reports real timings for this Python reference computation and analytically estimated ciphertext sizes. It does **not** claim that those timings are OpenFHE/BFV measurements, and it does not provide cryptographic privacy.

The assignment requires actual BFV/OpenFHE ciphertext evaluation and serialized ciphertext measurements. Those must be run in an OpenFHE-enabled environment before this can honestly be described as a fully complete Part 3 submission.

## Requirements
- Python 3.10+
- `pip install -r requirements.txt`

## Reproducible run
From this directory:

```bash
python -m venv .venv
source .venv/bin/activate        # Windows: .venv\\Scripts\\activate
python -m pip install -r requirements.txt
./run.sh                         # Windows: run commands individually below
```

Windows commands:

```powershell
python -m pip install -r requirements.txt
python -m pytest -q
python -m src.benchmark
python -m src.cli --password "Synthetic-Breached-Password!"
python -m src.cli --password "Definitely-Clean-Password!"
```

The benchmark writes `results/benchmark.csv` and `results/environment.json`.

## Repository layout
- `src/psi_reference.py` — encoder, bin builder, polynomial evaluation, reference PSI check, parameter definitions, size estimator.
- `src/cli.py` — command-line demonstration.
- `src/benchmark.py` — reproducible benchmark over 1k, 10k, and 100k synthetic entries.
- `tests/test_protocol.py` — correctness, normalization, case sensitivity, polynomial, and overflow tests.
- `results/` — benchmark outputs generated by `run.sh`.
- `report/` — evaluation report PDF and source.

## What the prototype verifies
1. Passwords are NFC-normalized before SHA-256; case is preserved.
2. Domain separation uses `CYB599-PSI-v1`.
3. The first 14 digest bits select one of 16,384 bins.
4. The next 64 digest bits are reduced modulo `t-1` and shifted to a nonzero field element.
5. Each bin is padded to a multiple-of-eight capacity and shuffled.
6. Membership is evaluated as a product of `(x-r)` over groups of eight roots; a root yields zero.
7. Synthetic breached and clean cases return the expected result.

## Parameter sets and security caveat
`BFV-P1` and `BFV-P2` are comparison budgets with `N=16384`, `t=549756174337`, and `log2(q)` budgets 300 and 350. Both are below the 411-bit quantum-security ceiling cited in Part 2. They are **not instantiated cryptographic contexts** here. OpenFHE must generate and validate the actual modulus chain and security level. Part 2's 8,192 ring-dimension option was rejected because its cited quantum modulus budget is insufficient for the design's combined noise/flooding requirements.

## OpenFHE completion required for full rubric compliance
Implement and run the encrypted backend using the official OpenFHE BFV API. Required measurements: key generation, client encryption of the three packed powers, server ciphertext multiplications/relinearization, plaintext-ciphertext polynomial accumulation, mask/noise-flooding and modulus switching, client decryptions, and actual serialized bytes for public/relinearization keys, query ciphertexts, and response ciphertexts. Do not label analytical size estimates or Python reference timings as these measurements.
